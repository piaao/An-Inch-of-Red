# 部署到线上 · 手机端可玩方案

> 这份文档回答两个问题：**怎么把这个游戏放到公网上**，以及**手机上到底能不能玩**。
> 所有数字都是实测的，不是估算；量的对象是**要发出去的那一份 `dist/`**
> （`scripts/verify_dist.mjs`，2026-09-27），线上数字另由
> `scripts/probe/live_payload.py` 对真链接量（同一组 URL、同一个口径）。
>
> **状态：已上线 → https://an-inch-of-red.app.workbuddy.host/**
> （一键发布，发的是 `dist/`；手机端 P0+P1 已实现并验收；P2 只差一行服务器配置，
> 账见 §5.2 —— 实测线上首屏 **2346.3 KB**，压 glb 后可再降到 **1095.8 KB**。）

## 1. 结论先行

| 问题 | 答案 |
|---|---|
| 部署难吗？ | **不难。** 纯静态、零后端、零第三方依赖，three.js 是本地 `vendor/`，不拉 CDN |
| 现在手机上能玩吗？ | **能。** 左半屏摇杆走、右半屏拖动转、三个按钮（跳/开门/暂停）。见 §3.P0 |
| 手机性能扛得住吗？ | **扛得住，而且很轻松。** 绘制调用 **21**、三角形 **5,886** |
| 真正的瓶颈是什么？ | **不是 GPU，是首屏要下多少。** 线上实传 **2346.3 KB / 118 个请求**；其中 `.glb` 占 1852.4 KB（79 %）且**没被压缩**。见 §3.P2 |
| 发什么？ | **`dist/`（221 个文件 · 5.80 MB）**，绝不要发仓库根。见 §5.1 |
| 已经发出去了吗？ | **是** → https://an-inch-of-red.app.workbuddy.host/ 。见 §5.1 |

一句话：**部署这件事本身很简单，手机端要重做的输入与信息排布已经做完了。**

### 线上首屏 2,346.3 KB 的构成（压缩后，实测）

| 来源 | 传输 | 解码 | 压到 | 还能怎么治 |
|---|---|---|---|---|
| `assets/models/` 81 个家具 .glb | 978 KB* | 994.1 KB | **100 %（没压）** | 与主人 .glb 合计 1852.4 KB → **gzip 后 601.9 KB**。见 §5.2 |
| `assets/actors/` 2 个主人 .glb | 858.4 KB | 858.4 KB | **100 %（没压）** | 骨架 + 5 条剪辑，内容动不了，但**可以被压** |
| `vendor/` three.js（3 个文件） | **266.0 KB** | 1,412.7 KB | 19 % | 平台已经 brotli 掉了，**这一笔不用再管** |
| `game/` 代码与数据（24 个） | ~225 KB | 458.2 KB | ~49 % | 已压 |
| `js/` + `css/` + 根页面 | ~19 KB | 84.0 KB | ~22 % | 已压 |

\* 家具 .glb 的传输值由总数倒算（1852.4 − 858.4），`live_payload.json` 有逐条记录。

🔴 **一个容易漏掉的顺序问题**：`play.js` 在 `start()` 里把 81 个模型**全部 `await` 装完**
（`play.js:463-467`）**之后**才 `openMenu()`（`play.js:561-564`）。所以**手机访客要等完
这 2.3 MB 才看得到菜单**，等待期间只有一条进度条。把菜单提到加载之前显示，是
性价比最高的一刀（P2）。

### 线上测量是怎么做的（以及为什么不能用浏览器）

不能像本地那样用无头 Chrome 打开真链接：**这个沙箱里无头 Chrome 导航到任何外网地址都会让
CDP 通道失联**（`Page.navigate` 拿不到响应，随后 `Runtime.evaluate` 也超时；拿
`https://example.com/` 复现，同样如此 —— 不是那个站点的问题）。

所以改成**不重算清单、只换口径**：`verify_dist.mjs` 把浏览器报过的 118 条
[路径, 解码字节] 落进 `work/dist_eval.json`，`scripts/probe/live_payload.py`
拿同一份清单到线上逐条 GET，只统计**实际收到的字节**（不自动解压，所以
`len(body)` 就是传输量）。两边是同一组 URL、同一个口径，可比。

线上实测额外确认了两件我原先以为要自己配的事：

- **`.glb` 的 MIME 平台已经给对了**（`model/gltf-binary`），不需要配 nginx；
- **gzip/brotli 默认是开的**（33 个文本资源走 `br`）。
- 唯一一条 404 是 `assets/audio/manifest.json` —— 这是**有意的降级链**（见
  `game/MUSIC.md`：没有 manifest 就退回浏览器内程序化合成），不是缺文件。

## 3. 手机端改造：三档，按"能不能玩"排序

### P0 · 触屏输入 —— ✅ 已完成

`game/play/touch.js`（330 行）+ `play.html` 的 9 个 DOM 节点 + `css/play.css` 的样式
+ `config.js` 的 `TOUCH` 旋钮。**核心（`game/core/*`）、物理、`Avatar`、
`VERDICT.md` 的胜率一个字都没改。**

| 输入 | 做法 |
|---|---|
| 移动 | 左半屏**浮动原点**虚拟摇杆 → `fwd` / `side`（值域 [-1,1]，与键盘同语义） |
| 转向 | 右半屏拖拽 → 直接累加进 `play.js` 那个**本来就每帧清零的 `look` 累积器** |
| 跳跃 | 右下按钮 → 与 `Space` 同义（`input.jump`） |
| 开门/推柜 | 右下按钮 → 走 `__play.interact()` 那条路 |
| 暂停 | 小按钮 → `togglePause()`；暂停后触屏层收起 |
| 桌面不受影响 | 能力探测只决定**绑不绑**事件，不改桌面那条路 |

三条刻意选择，每一条都是为了"手机不是另一个游戏"：

1. **视角走鼠标那一个累加器。** 手机上转视角用的还是 `MOVE.mouseSens`，
   只多一个"手指比鼠标抖"的倍率 `TOUCH.turnGain`。**第二条换算链会漂，这一条不会 ——
   它根本不存在**（实测：横拖 150 px 累加进 look = 150 × turnGain = 202.5，与
   `__play.look` 转过的角度逐位相同）。
2. **摇杆模长 ≤ 1。** 键盘斜向不加速，摇杆也天然落在单位圆内 ——
   于是**触屏永远跑不过键盘**（实测斜向 |v| = 1.000000309，误差来自 6 位小数量化）。
   不然手机上量到的胜率和桌面上量的不是同一个数字。
3. **相位一问即答。** 构造函数拿到 `phase: () => S.phase`，而不是五处地方各自记得
   调 `setPlaying()`。同一件事有五个写入点，就是五个会漂的地方。

**能力探测放在 `touch.js` 而不是 CSS**：`@media (hover:none)` 在带触屏的笔记本上是
假阳性，而"桌面浏览器一进来就多出一层摇杆"比"手机上没有摇杆"更糟。`?touch=1` /
`?touch=0` 是留给"带触屏的笔记本"和验收脚本的显式开关 —— 探测只能回答"有没有"，
回答不了"这一次想不想用"。

顺手修掉的一处：`js/open-guard.js` 在页面起不来时会告诉访客「双击 `start.bat`」或
「执行 `python serve.py`」—— 这句话对本机是对的，**对线上访客是无法执行的废话**。
现在按 host 分支：只有本机才说那一套。

**`pointerlockchange` 的自动暂停不用管**：它被 `hadLock` 守着（`play.js:1342-1344`），
触屏下永远拿不到锁、`hadLock` 一直是假 —— **这个安全性是靠构造保证的，不是靠特判**。

### P1 · 窄屏信息重排 —— ✅ 已完成

见 §2 的「改造前 / 改造后」表。另外补了 `<meta name="viewport">` 的
`viewport-fit=cover` 与 `env(safe-area-inset-*)`，让刘海与手势条不压内容。

已就位、不用再做：`css/play.css:36` 有 `user-select:none`，`:45` 有
**`touch-action:none`**（浏览器手势已经被压住），`:567` 已有一个
`@media (max-width:700px)` 块做基础收窄。

### P2 · 首屏瘦身 —— 服务器那半已经不用做了，只剩代码那半

上线后实测改变了这一节的排序（原以为"开 gzip"是最大一笔，其实平台默认就开了）：

1. ~~服务器开 gzip/brotli~~ —— **平台已经开了**（`br`），three.js 1.4 MB 已经压到 266 KB。
   但 **`.glb` 没压**（1852.4 KB → 可压到 601.9 KB）。这一刀 A 方案管不了，账见 §5.2。
2. **菜单提到模型加载之前** —— 见 §2 的顺序问题。**零网络收益，但体验收益最大**，且任何方案下都能做。
3. **合并 81 个 .glb 成一个 pack** —— 省的是 81 次 RTT，不是字节。工作量最大，最后做。

## 4. 四条量出来的教训（写下来免得下次再踩）

### 4.1 探针自己会"死了但不说"

第一版探针挂满 9 分 35 秒、零输出。根因不在被测对象，在**探针自己**：
`launch()` 20 秒超时会抛错，而 `serve()` 放在了 `try` **之外** —— 抛错后静态服务
没人关，node 挂在事件循环上**永不退出**；再加上 `| tail` 会把输出憋到 EOF，
于是「报错了」看起来像「卡住了」。

→ **教训**：`serve()` 进 `try/finally`；输出**逐行落盘**而不是靠管道缓冲；加看门狗。

### 4.2 "还在加载" ≠ "页面没起来"

第二版把 `launch` 修好了，却报「页面没起来，`playError=null`」—— 而 `playError` 是空、
控制台零异常、零失败请求，这组合只说明一件事：**还在装载**。`play.js` 把模型一个个
`await kit.load()`。我只 `settle: 1500` 就下了判断。

→ **判据三件套**：`__playError` 有值＝真崩；`__playBooted` 真而 `__ready` 假＝
模块图跑起来了、还在加载；两个都假＝模块图根本没跑。

### 4.3 bounding-box 说"零越界"，截图说"不可玩"

自动检查报告「越界元素 0 个」——**技术上完全正确**，因为没有任何元素超出视口边界。
但截图一看：小地图占了屏宽 67 %，底部提示折成四行，可玩区域只剩中间一条。

→ **教训**：越界检查只能抓"溢出"，抓不到"布局虽然合法但吃掉了屏幕"。
窄屏验收必须**同时**看数字与截图，并把「可玩区域占比」当成一条指标。

### 4.4 量具自己会漏一层、会认错指标（三条，都在 `verify_dist.mjs` 上抓到）

**(a) 目录只走一层。** 递归列文件的那段只走了 `base` + 直接子目录，于是 **228 个文件
被数成 33 个**，而漏掉的恰好是 `assets/models/*.glb` 与 `assets/actors/*.glb` ——
**最该被检查的那两个目录**。症状是自相矛盾的报账：`dist 体积 1859.7 KB` 却印出
`首屏 3807.3 KB`（比整包还大）。更要紧的是「禁运路径一个都不在 dist 里」这条
**安全检查**只扫了 33 个文件 —— 往里层塞一个 `配置.yaml` 是扫不出来的。

→ 修好之后加了一条**自洽断言**：`首屏字节 ≤ 整包字节`。两行数字互相打脸时，
应该有一条断言先炸，而不是等人去发现。

**「安全断言扫了一半的文件」比没有断言更危险 —— 因为它给的是虚假的安心。**

**(b) 判据用错了代理指标。** 原来第 2 条是「零失败请求」，直接数 CDP 的
`Network.loadingFailed` 事件。它把两种完全不同的东西印成同一个样子
（`cdp.js:235-238` 的注释早就点明了）。实测证据：

- 事件形态是 `net::ERR_ABORTED  canceled=true  type=Fetch`，而 **status=200**；
- 同一文档里**每个 URL 只请求了一次** —— 不是重复请求；
- `host_male.glb` 收到 **453,708 B**，磁盘上是 453,496 B —— 字节**完整送达**；
- 每一轮"被取消的是哪一条"都不同（时序相关）；
- 而同一轮里 `hosts.source === 'files' && cast = male,female` ——
  两个主人**真的解析成了骨架**，字节没到是不可能解析成功的。

→ 结论：这是**渲染器放掉了一条已经送达的流**（收尾动作），不是"服务器拒绝"。
判据换成直接问那个真正的问题：**有没有哪个文件从来没拿到过 2xx**
（`verify_dist` 现在还会印出 `121 个 URL · 120 个 2xx`）。这条**比原来更严** ——
它还顺手证明了"81 个家具 + 2 个主人一个都不缺"，而原来的代理指标从没验证过这一点。

**「量一个容易量到的数，不等于量到了想问的问题。」**

**(c) 一份过期的 `dist/` 也能全绿。** 上面每一条断言都是在 `dist/` 身上量的，
所以**改了源码忘了同步 `build_dist.py`，所有检查照样通过，而线上跑的是上一版**。
这是这类流水线最安静的失败方式。

→ 加了一条 `dist 与当前源码逐字节一致（不是一份旧的剪影）`。它**第一次运行就抓到了
东西** —— 我刚编辑过 `DEPLOY.md`，而 `dist/` 里还是旧的。

顺带就牵出两件真事：

1. **7 份设计书一直在被发到公网**（`game/` 是白名单目录，于是 `DEPLOY.md` /
   `VERDICT.md` / `ACTORS.md` / `PROPS.md` / `MUSIC.md` / `MAPS.md` / `NAME.md`
   一起被收进去了）。它们**不是运行所需**：运行时代码对 `.md` 的引用全在注释里，
   没有一处 `fetch()`。现在按扩展名筛掉（脚本会**打印筛掉了哪几个**，不静默）。
2. **`build_dist.py` 不再整目录删**。原来的 `shutil.rmtree` 有 228 个删除目标，
   会撞上本机的批量删除保护，脚本半路死掉、`dist/` 留在半新半旧的状态 ——
   而"重建"这件事看起来本该是原子的。改成**增量同步**（本次：写入 0 个、清掉 7 个）。

`dist/` 里只留 `play.html` 一个页面，正好避开"多页面时发布工具分不清发哪一页"的坑。

| `.glb` MIME | **`model/gltf-binary`** —— 平台自己就是对的，不需要配 nginx |
| 压缩 | **默认就开**：33 个文本资源走 `br`，1 个 `gzip`。three.js 1,304,820 → **266,043 B** |
| 首屏 | **2346.3 KB**（本机无压缩是 3807.3 KB，省 38 %） |

当初这张表里的三选一，A 和 B/C 的差别有一半被实测推翻了 —— **"响应头不可控"里的
gzip 与 `.glb` MIME 都不用自己管**：

| 方案 | 优点 | 代价 | 实测 |
|---|---|---|---|
| **A. 一键发布**（WorkBuddy 内置）✅ 已用 | 最短路径，几秒出分享链接；不用管证书与备案 | 链接是平台域名；`.glb` **没被压** | gzip/br 开、MIME 对；`.glb` 是唯一没压的 |
| **B. 自己的阿里云 + nginx** | 自己的域名、能配 gzip/HTTP2/HTTPS，也是你在用的那台 | 要配 `.glb` 的 MIME、备案、证书 | 仍值得做，唯一理由是**能压 `.glb`**（见 §5.2） |
| **C. GitHub Pages** | 仓库已经公开，零成本 | 同样只能发 `dist/`；没有压缩开关 | 不推荐：`.glb` 那 1.85 MB 会原样发出去 |

如果哪天换到 B，这几行就是首屏最大的一笔（**不动代码**）：

```nginx
# .glb 实测能压到 32.5% —— 首屏 2346.3 KB → 1095.8 KB
types { model/gltf-binary glb; }
gzip on;
gzip_types text/css application/javascript application/json model/gltf-binary;
gzip_min_length 1024;
# 更狠一档（约再省 5%）：
brotli on; brotli_types text/css application/javascript application/json model/gltf-binary;
```

### 5.2 要不要做 P2 —— 现在只剩一笔

线上实传 2346.3 KB 里，**`.glb` 占 1852.4 KB（79 %）且一个字节都没压**。
本地实测 `gzip -6`（nginx 默认档）：

```
.glb  83 个   1852.4 KB → 601.9 KB（32.5%）  省 1250.5 KB
→ 首屏 2346.3 KB 掉到 1095.8 KB（再降 53%）
```

所以顺序是：

1. **让服务器压 `.glb`** —— 一行配置，首屏直接砍一半。这是现在性价比最高的一刀。
   平台这边（A）管不了响应头，所以这一刀要么换 B，要么把 `dist/` 里的 `.glb`
   **预先压成 `.glb.gz`** 由前端自己解（麻烦，不推荐）。
2. **菜单先于模型显示**（`play.js:463` / `play.js:561`）—— 零网络收益，但把"等 10 秒
   黑屏"变成"立刻看到菜单 + 进度条"。**这是纯代码改动，A 方案下也能做。**
3. 模型打包/合并（把 81 个 .glb 合成几个）—— 收益是 81 次 RTT，工作量最大，最后做。
